# Wardex v1.8.0 Release Notes

**Release Date:** 2026-04-24
**Version:** 1.8.0
**Theme:** Risk Posture Orchestration (RPO) Platform

---

## Highlights

### Orchestration Command (`wardex assess`)
A unified command for multi-layer compliance and asset-based assessment, tying
controls, assets, and evidence into a single posture view.

**Impact:** one entry point replaces ad-hoc invocations for full regulatory
footprint analysis.

### Layer Delta Analysis
Automatic identification of **Paper Security** (documented-only) and **Shadow
Security** (implemented-only) controls from layer deltas.

**Impact:** closes the documented-vs-implemented blind spot that manual reviews
routinely miss.

### Risk-Based Scoring v2
Roadmap prioritization formula now incorporates `ContextWeight` and
`Effectiveness`, replacing the previous flat scoring approach.

**Impact:** remediation ordering reflects real exposure and compensating
control strength.

### Asset Compliance Models
Context-aware scoring per business system with Criticality, Exposure, and
Threats.

---

## Detailed Changes

### Added
- **Orchestration command (`wardex assess`)**: unified multi-layer,
  asset-based assessment pipeline.
- **Risk-Based Scoring v2**: `ContextWeight` + `Effectiveness` in the roadmap
  prioritization formula.
- **Flexible ingestion**: root-level list support in YAML/JSON control and
  asset definitions.

### Changed
- **BREAKING — Architectural Flattening**: consolidated `pkg/accept` into a
  unified high-performance package.
- **Coverage strictness**: the global coverage metric now requires the
  `implemented` layer for a `Covered` status.
- Documentation overhaul (Playbook + Technical View) for the RPO transition.
- Purged legacy PoCs; reorganized research data.

### Fixed
- **Deduplication logic**: `LoadMany` correctly handles same-ID controls across
  different layers via `ID|Layer`.
- **Model inconsistency**: `Asset` schema updated to support advanced exposure
  context and threat scenarios.

---

## Compatibility

- `wardex assess` is additive; `wardex evaluate` continues to work as before.
- Breaking changes confined to internal `pkg/accept` consolidation and coverage
  semantics.
