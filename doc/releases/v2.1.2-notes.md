# Wardex v2.1.2 Release Notes

**Release Date:** 2026-06-22
**Version:** 2.1.2
**Theme:** CRA-Ready Gate — Syslog, PKI, Dry-Run & Helm

---

## Highlights

### Mandatory EPSS Enrichment
EPSS enrichment is now enforced for CRA compliance — gate decisions can no
longer silently run on stale or missing exploitation-probability data.

**Impact:** release gates rest on fresh, real-world exploit data.

### Syslog Forwarding
Structured RFC 5424 dispatch of gate decisions, acceptances, and Art14
lifecycle events via `WARDEX_SYSLOG_ENDPOINT` (TCP/UDP/TLS). Opt-in at startup.

**Impact:** SIEM/observability pipelines receive gate events in real time.

### PKI Mode
Ed25519 CA for certificate-based identity: `wardex pki init`, `wardex pki
issue`. Sealed configs carry X.509 chains.

### Dry-Run Mode
`wardex evaluate --dry-run` prints what *would* happen without writing
artefacts or producing exit codes.

**Impact:** safe CI rehearsal before real enforcement.

### Helm Chart & Compose
`deploy/helm/wardex/` (v0.1.0, appVersion 2.1.2) with Job/CronJob, KEV init
container, PVC, seccomp, distroless nonroot. `docker-compose.yml` for local
Postgres (audit store) + MinIO (artefacts) + API stub.

## Detailed Changes

### New Commands / Flags
- `wardex evaluate --dry-run`.
- `wardex pki init` / `wardex pki issue`.
- `wardex accept verify --output <path>` — JSON verification report artefact.
- Syslog forwarding via `WARDEX_SYSLOG_ENDPOINT`.

### New Exit Codes
| Code | Semantics |
|------|-----------|
| 4 | Tampered / StoreInconsistent (distinguishes tampered acceptances from store inconsistency) |

### Package/API Changes
- **Breaking**: `catalog.Load()` now returns
  `([]model.CatalogControl, error)`.
- **Breaking**: `sdk.LoadFramework()` returns an error.

### Tests & Coverage
- SDK coverage 46% → 91% (20 new tests in `pkg/sdk/`).
- CLI coverage 13.3% → 35.8% (13 new execution tests for panic/recover in
  `pkg/accept/cli/`).
- CI test scope `./...`, coverage threshold 40%, HTML coverage artefact.

### Changed
- CLI refactoring: 7 `Run` handlers → `cmd/evaluate/cli_handlers.go`; `cli.go`
  uses `exitFunc` (mockable), `stderr` (io.Writer), `acceptCfgPath`.
- Flags split into Core / Advanced groups in `wardex evaluate --help`.
- Standardized table output across all CLI commands with shared `pkg/ui`.

### Security
- GPG-signed `main` commits (key `979AC8CE8F357652`); `commit.gpgsign true`.
- Helm chart defaults: `runAsUser: 65532`, read-only root FS, all capabilities
  dropped.

### Fixed
- `catalog.Load` error propagation; `signer.go` HMAC secret hint;
  `frameworks/technological_controls.yml` schema (use `name` field,
  maturity + layer).

## Compatibility

- `catalog.Load()` / `sdk.LoadFramework()` signature changes are breaking for
  SDK consumers — update call sites to handle errors.
- Exit code `4` new; existing tampered acceptances previously surfaced as a
  generic store error.
