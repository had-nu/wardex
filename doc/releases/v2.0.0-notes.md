# Wardex v2.0.0 Release Notes

**Release Date:** 2026-06-10
**Version:** 2.0.0
**Theme:** EU CRA Article 14 Enablement

---

## Highlights

### CRA Article 14 Enablement
Wardex generates structured notification artefacts for the EU Cyber Resilience
Act Article 14(2) three-phase reporting obligation (early warning, notification,
final report), managed via the new `wardex art14` subcommand
(`list`, `show`, `mark-dispatched`, `finalize`, `verify`).

**Impact:** operational compliance with mandatory incident-notification
timelines straight from the CLI.

### Active Exploitation Hard Stop
`wardex evaluate` exits with code `12 = ActivelyExploited` when a vulnerability
is marked `actively_exploited: true`. The hard stop cannot be overridden by risk
acceptances.

**Impact:** actively exploited CVEs can never silently pass a release gate.

### KEV Correlation
`wardex convert grype` gains `--kev`, correlating CVEs against the CISA Known
Exploited Vulnerabilities catalogue and setting `actively_exploited`,
`exploited_source`, and `actively_exploited_since`.

### Audit Chain Integrity
Gate audit entries are cryptographically chained via SHA-256
`previous_entry_hash`; `VerifyChain()` detects tampering and gaps.

**Impact:** the gate audit log becomes tamper-evident evidence.

### Gate Decision Log, Provenance & Forwarding (G1–G3)
- **G1 — Gate Decision Log**: every decision recorded in `wardex-gate-audit.log`
  (configurable via `--gate-log`), with config hash, evidence hash, overall
  decision, and risk score.
- **G2 — Evidence Provenance**: `converted_by` field in evidence envelopes;
  `--strict` warns/refuses non-canonicalised evidence.
- **G3 — Log Forwarding**: gate decisions integrated with the `Forwarder`
  interface; real-time Syslog dispatch via `reporting.gate_log.forward`.

## Detailed Changes

### New Commands / Flags
- `wardex art14 list|show|mark-dispatched|finalize|verify`.
- `wardex accept active-exploit` — records operator awareness of active
  exploitation in the chained audit log.
- `wardex convert grype --kev` — CISA KEV correlation.
- `wardex evaluate --gate-log <path>` — gate decision log location.

### New Exit Codes
| Code | Semantics | Origin |
|------|-----------|--------|
| 12 | ActivelyExploited | hard stop |

### ENISA Backend (stub)
New `enisa` forward backend writes to a local JSONL queue file. No network
transmission — awaiting the ENISA Article 16 API publication.

### Configuration
New `cra.art14` and `reporting.enisa_queue` blocks in `wardex-config.yaml`.

### Package/API Changes
- **BREAKING**: `VulnerabilityEnvelope` has optional `evaluated_at`.
- **BREAKING**: `Vulnerability` gains `actively_exploited`,
  `actively_exploited_since`, `exploited_source`.
- **BREAKING**: `AuditEntry` gains `previous_entry_hash`,
  `actively_exploited_cves`, `art14_deadline_early_warning`,
  `art14_deadline_notification`, `art14_notification_artefact_path`.
- `model.AuditEntry` extended with `evidence_hash`, `overall_decision`; new
  `model.VulnerabilityEnvelope`.

### Fixed
- `cmd/art14/art14.go:runVerify` now uses mockable `exitFunc` instead of
  `os.Exit`, enabling tampered-verification testing.
- `doc/examples/wardex-config.yaml` updated with the `gate_log` block to pass
  `KnownFields(true)` schema validation.

---

## Compatibility

- Exit code `12` is new — CI pipelines should handle it explicitly.
- Legacy configs remain valid; new `cra.art14` / `reporting` blocks are
  optional.
- Older audit logs without `previous_entry_hash` are accepted by the verifier
  (genesis entries).
