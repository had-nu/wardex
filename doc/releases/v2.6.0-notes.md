## Highlights

### Unified CPL Chain Format (P0)
Runtime and verifier now agree on one chain format: canonical
`previous_entry_hash`, genesis = absent/empty (legacy `"genesis"` accepted).
`wardex audit verify-chain` no longer reports false positives on real logs, and
schema evolution is codified with migrations instead of silent format switches.

**Impact:** the audit chain and its verifier can never diverge again.

### Migration Chain + Release-Seal Ancestry (L1, L4)
`cpl_schema_version` lives in the audit envelope — the CPL content hash stays
stable. `wardex gate check-version` refuses re-sealing an already-sealed version
(exit `13 = DuplicateRelease`); `--release-version` and `--policy-ref` are
mandatory in release-seal mode.

**Impact:** silent re-releases become impossible; policy provenance is enforced.

### Streaming Verify + Cursor-Paginated SIEM Export (L5)
`pkg/auditlog` streams entries line-by-line (bounded per line); new
`wardex audit export --limit N --cursor <sha256>` delivers LIMIT+1 semantics with
`has_more` and resume-by-chain-hash.

**Impact:** long audit logs can be checked and shipped without unbounded memory.

### Encrypted Key Envelopes (L6, opt-in)
`wardex keygen --encrypt` writes `WARDEX-KEY-V1` envelopes (Argon2id +
AES-256-GCM, verification tag before decrypt); `trust`/`provenance` decrypt
in-memory with zeroize. Legacy plaintext keyrings keep working.

**Impact:** keys-at-rest are encrypted for anyone who opts in (default 0400
plaintext preserved for automation).

### Risk-Class Gate Exams (L3)
`--gate-class pr|deploy|nightly` profiles the gate against the risk of the
run with per-gap severities `block|advisory|off`; new exit
`6 = FreshnessAdvisory`. The GitHub Action gains a `gate-class` input.

**Impact:** staged gates with different strictness per pipeline stage.

### Article 14 Artefact Versioning (L2)
Notification artefacts carry `format_version: 1` and a `capabilities` bitmap
(HMAC-SHA256 | canonical JSON; CBOR v1 declared). Verification rejects future
versions with a controlled error — no silent downgrade. Pre-2.6 artefacts still
verify.

### Forced-Upgrade Tripwire Kill-Switch (L7)
`release_gate.forced_upgrade.{enabled,deadline,tripwire_failures}` arms the gate
when vulnerability attestation is not fresh and blocks unattested releases
(exit `10`); N consecutive failures (default 5) disarm it with a
`forced_upgrade.disarmed` audit entry and fresh evidence re-arms it. No Gleipnir
dependency — evidence comes from Wardex's own sources (EPSS/KEV).

## Detailed Changes

### New Commands / Flags
- `wardex audit export --limit N [--cursor <sha256>] [--tail]` — SIEM export
  (`cmd/audit/export.go`).
- `wardex gate check-version --audit-log … --version X` — duplicate-release guard
  (`cmd/gate/`).
- `wardex keygen --encrypt [--passphrase]` — encrypted key envelopes
  (`cmd/keygen/`, `pkg/keys`).
- `wardex evaluate --gate-class <class>` and `--gate-class` input on the Action
  `run-gate` job.
- `wardex evaluate --forced-upgrade [--forced-upgrade-state]` — kill-switch
  activation for local/CI runs.

### New Exit Codes
| Code | Semantics | Origin |
|------|-----------|--------|
| 6 | FreshnessAdvisory | L3 |
| 13 | DuplicateRelease | L4 |

### Package/API Changes
- `pkg/model/audit.go` — `cpl_schema_version` (envelope), events
  `forced_upgrade.{armed,disarmed}`; `PrevHash` deprecated (fallback only).
- `pkg/model/art14.go` — `FormatVersion`, `Capabilities` + capability bitmap.
- `pkg/keys` (new) — Argon2id + AES-256-GCM envelope (WARDEX-KEY-V1).
- `pkg/enrich` — tripwire counter (`TripwireState`, `Step`).
- `internal/cpl/chain.go + verifylink.go` — canonical `previous_entry_hash`;
  version-aware `VerifyLink`.
- `internal/policy` — strict loader (P7) with lenient v1 fallback (P6) and
  declarative `Migrate(doc, from, to)`.
- `pkg/auditlog` (new) — streaming reader; `internal/cpl` and `cmd/audit` use it.
- `config/config.go` — `config_schema_version`, `ReleaseGate.ForcedUpgrade`,
  `GateOptions` class fields (`gate.classes`).
- `pkg/orchestrator` — class profile resolution and forced-upgrade stage.

### Docs
- CDDL (RFC 8610): `spec/cddl/cpl-entry.cddl` updated (canonical
  `previous_entry_hash`, `prev_hash` deprecated); new
  `spec/cddl/art14-notification.cddl` and `spec/cddl/tripwire-state.cddl`.
- README / README-en: *What's New — v2.6.0* block; Licensing section now carries
  an Attributions line.
- `ACKNOWLEDGMENTS.md` (new): canonical third-party provenance (Nym, Apache-2.0).
- CHANGELOG: full `[2.6.0]` roll-up of Phases 0–4.

## Compatibility

- All changes additive and backward-compatible; parsing of legacy formats
  retained (P2) — no config hash breakage.
- L6 is opt-in; existing 0400 plaintext key files remain valid.
- Exits 6 and 13 only occur when the new features are actually used.

## Rollback

- Reverting the merged P0 commit restores the legacy chain format; `prev_hash`
  and lenient v1 parsing remain accepted throughout.
