# Wardex v2.2.2 Release Notes

**Release Date:** 2026-07-06
**Version:** 2.2.2
**Theme:** Cordyceps Hardening

---

## Highlights

### Supply-Chain Fixes (CI-1, CI-2)
- Syft installation replaced `curl | bash` with a pinned binary download +
  SHA-256 checksum verification; hash shown in CI logs for PR diff visibility.
- Branch-triggered Docker images now use a `dev-` namespace prefix and are
  signed immediately with cosign (removed the tag-only gate).

**Impact:** no unpinned scripted installs; every image, dev included, is
signed.

### Path Traversal via Symlink Bypass Fixed (CI-3)
Replaced `utils.SafePath` with `cli.ValidateInputPath`/`cli.ValidateOutputPath`
using `filepath.EvalSymlinks` before containment checks. 33 call sites across
19+ files migrated; TOCTOU fixed in `pkg/accept/accept.go` (validated path now
used for writes) and `cmd/evaluate/evaluate.go` (`--out-file` validates before
`os.Create`). 33 tests including symlink escape, null bytes, shell injection,
pseudo-filesystems.

**Impact:** workspace escape via symlink tricks is closed end-to-end.

### Trust & Config Visibility
New read-only commands:`wardex trust list|show|verify`, `wardex config show`,
`wardex auth status`, `wardex auth verify --actor` — inspect the full
cryptographic governance layer without side effects.

## Detailed Changes

### Security
- **CI-1**: syft pinned binary + SHA-256 verification ([PR #96]).
- **CI-2**: `dev-` image namespace + immediate cosign signing ([PR #97]).
- **CI-3**: `pkg/cli/pathguard.go` — central path validation
  (`ValidateInputPath` for reads, `ValidateOutputPath` for writes); symlink
  resolution via `filepath.EvalSymlinks`; pseudo-filesystem rejection
  (`/proc/`, `/sys/`, `/dev/`) in output paths ([PR #98]).

### Added (Usability)
- `wardex trust list` / `trust show <id>` / `trust verify` — key status, role,
  metadata, revocation, signatures (`cmd/trust/trust_extended.go`).
- `wardex config show` — risk appetite, gate mode, CRA Art.14 status, state
  store status, SHA-256 hash (`cmd/configseal/show.go`).
- `wardex auth status` / `auth verify --actor` — trust store integrity and
  actor permissions (`cmd/auth/auth.go`).
- `wardex contract verify` — SHA-256 contract hash verification
  (`cmd/contract/verify.go`).
- `wardex assets inventory` — ICT asset inventory (criticality, exposure,
  zone, owner); table/JSON/CSV (`cmd/assets/inventory.go`).
- `wardex hmac sign` — HMAC-SHA256 file signature from
  `WARDEX_ACCEPT_SECRET` (`cmd/hmac/sign.go`).
- `wardex convert kev` — CISA KEV catalogue → Wardex YAML
  (`cmd/convert/kev_cmd.go`).
- `wardex chain seal` — SHA-256 chain-seal manifest + collection hash
  (`cmd/chain/seal.go`).

### Fixed
- `policy validate/list` accepts `*.yaml` too.
- `art14 verify` shows actionable instructions when `WARDEX_ACCEPT_SECRET` is
  unset.
- `audit verify-chain --session-id` filters multi-segment chains.
- `state status/verify` hints to enable `state_store.enabled=true`.

## Compatibility

- `utils.SafePath` removed; the `pkg/cli/pathguard` API is the replacement.
- All new commands are additive and read-only where inspection-oriented.
